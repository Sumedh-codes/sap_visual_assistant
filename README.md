# SAP Screenshot Extraction Using Vision and OCR

A Python prototype that extracts structured information from SAP-style screenshots using two approaches: a vision-only Azure AI model and a hybrid OCR + vision pipeline. The outputs are structured JSON files that can be validated against predefined schemas and evaluated against manually annotated reference data.

## Features

- **Vision-only extraction:** Sends screenshots directly to an Azure AI vision-capable model.
- **OCR + vision extraction:** Uses PaddleOCR to identify text, creates masked images, and combines OCR results with vision-model analysis.
- **Structured JSON output:** Produces machine-readable data describing screen titles, transaction codes, UI elements, field values, and uncertainty.
- **Schema validation:** Checks whether generated JSON conforms to the expected output structure.
- **Automated evaluation:** Compares both pipelines against reference annotations and generates CSV, JSON, and Markdown reports.
- **Privacy-aware processing:** Includes a masking stage in the OCR pipeline. Masking should be reviewed before any image is sent to an external model.

## 📂 Results Directory Index

This section provides a guide to the generated outputs and evaluation artifacts for both SAP screenshot extraction pipelines: **Vision-Only** and **OCR + Vision**.

### 1. Output Directories

| Folder / File | Description | What to Look For |
|---|---|---|
| `output/` | Contains the results generated by the **Vision-Only pipeline**. Screenshots are processed directly by a vision-capable LLM without a separate OCR stage. | Extracted SAP screen information and structured output generated directly from screenshots. |
| `ocr_output/` | Contains the results generated by the **OCR + Vision pipeline**. OCR extracts text from the screenshot, which is then used alongside vision-based processing. | Extracted SAP screen information produced using the combined OCR and vision approach. |

### 2. Evaluation Results and Comparison Report

The evaluation artifacts are stored in the `evaluation_result/` directory. They summarize the performance of both pipelines using the same evaluation dataset and reference annotations.

| File | Format | Description |
|---|---|---|
| `evaluation_result/evaluation_result.md` | Markdown | Human-readable evaluation and comparison report. Use this file first to understand the results, compare the two approaches, and review the key findings. |
| `evaluation_result/evaluation_result.csv` | CSV | Detailed, tabular evaluation results that can be opened in Excel, analyzed using Python, or used to create charts. |
| `evaluation_result/evaluation_summary.json` | JSON | Machine-readable summary of the evaluation results, suitable for programmatic analysis and integration with other tools. |

### 3. Which File Should You Open?

| If you want to... | Open |
|---|---|
| See the results of direct vision-based extraction | `output/` |
| See the results of the OCR + Vision approach | `ocr_output/` |
| Read the overall comparison and findings | `evaluation_result/evaluation_result.md` |
| Inspect detailed evaluation metrics in a spreadsheet | `evaluation_result/evaluation_result.csv` |
| Access the summarized evaluation data programmatically | `evaluation_result/evaluation_summary.json` |

### 4. Evaluation Overview

The evaluation compares the Vision-Only and OCR + Vision pipelines using criteria such as:

- **Text extraction accuracy** — how accurately the system identifies text from SAP screenshots.
- **Field-value association** — whether extracted values are associated with the correct labels or fields.
- **Bounding-box IoU** — how closely predicted text or field regions align with reference bounding boxes, where applicable.
- **JSON validity** — whether the generated structured output conforms to the expected format.
- **Unsupported claims and uncertainty** — whether the system produces information that is not supported by the screenshot and how it handles uncertain results.
- **Processing time** — how long each pipeline takes to process a screenshot.

The Markdown report contains the human-readable comparison, the CSV supports detailed analysis, and the JSON summary provides a machine-readable representation of the evaluation results.

**Note:** The evaluation report and summary should be treated as the source of the actual measured results. This index describes where the artifacts are located and how to use them; it does not imply that either pipeline performs better before the results are examined.


Generated output directories and filenames may vary depending on the input paths used. The reference annotations are used for evaluation and should be reviewed for correctness.

## Requirements

- Python 3.10 or later, compatible with the project's dependencies
- An Azure AI Foundry deployment that supports image input
- Azure endpoint, API key, and deployment configuration
- Internet access for API requests

## Setup on Windows PowerShell

Run these commands from the project root directory:

```powershell
cd <project_folder>

py -m venv .venv
.\.venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
pip install -r requirements.txt
```

If PowerShell blocks virtual-environment activation, use the Python executable directly:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

### Configure Azure AI Foundry

Create a local `.env` file based on `env.example`:

```powershell
Copy-Item env.example .env
```

Edit `.env` and enter the endpoint, API key, and deployment name expected by the code.

**Never commit `.env` or expose API keys.** Keep credentials private and ensure `.env` is excluded through `.gitignore`.

The client configuration depends on the endpoint and API format supported by your specific deployment. Follow the deployment's documented sample if adjustments are required.

## Evaluating Both Pipelines

After generating the outputs for the reference screenshots, run:

```powershell
python src/evaluation.py
```

The evaluation script compares the generated outputs against `data\reference\sap_manual_reference_output.json`.

It produces:

| File | Purpose |
|---|---|
| `evaluation_results.csv` | Per-screenshot evaluation results |
| `evaluation_summary.json` | Aggregate metrics in JSON format |
| `evaluation_report.md` | Human-readable comparison report |

All reports are saved in `evaluation_results/`.

### Evaluation metrics

The evaluator reports metrics including:

- Processing success rate
- JSON parsing and schema-validity rates
- Screen title and transaction-code accuracy
- Element precision, recall, and macro F1
- Field-value association accuracy
- Uncertainty-handling accuracy, where applicable

Element matching uses normalized labels, with fallback matching where labels are absent. Field-value association is assessed using normalized label-value pairs. Bounding-box intersection-over-union (IoU) is not currently evaluated.

## Limitations

- **Small evaluation set:** Testing covers 15 synthetic SAP-style screenshots. Generalization to real SAP production screens has not yet been established.
- **Element extraction accuracy:** Current macro element F1 scores are relatively low, indicating that UI-element detection and matching require further improvement.
- **OCR errors:** Dense tables, small fonts, unclear text, and overlapping UI components can cause missed or incorrect detections.
- **Model-generated errors:** A valid JSON response can still contain incorrect values, omitted elements, or unsupported inferences.
- **Reference-data dependence:** Evaluation scores depend on the quality and completeness of the manually annotated reference outputs.
- **Bounding-box evaluation:** Bounding-box IoU is not currently included in the evaluator.
- **Privacy and security:** SAP screenshots may contain confidential business or personal information. Use synthetic or approved redacted data, and verify masking before transmitting screenshots to an external API.
- **Deployment dependency:** Availability, image support, output-token limits, and API compatibility depend on the configured Azure deployment.

## Troubleshooting

| Problem | What to check |
|---|---|
| HTTP 401/403 | API key, endpoint, deployment permissions, and access |
| HTTP 404 | Deployment name and endpoint/API format |
| HTTP 400 | Whether the deployment supports image input and the request format is correct |
| Truncated JSON | Output-token limit and model response finish reason |
| Missing output file | Input filename, output directory, and terminal error messages |
| Schema validation failure | Required fields, value types, and the relevant schema |
| Low element F1 | Inspect reference annotations, matching rules, and per-screenshot errors |
